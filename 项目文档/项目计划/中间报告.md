## 二、性能数据

### 2.1 纯推理性能（Day 8 实测，snpe-throughput-net-run）

| 模型 | 版本 | 后端 | 吞吐 | 单帧延迟 |
|------|------|------|------|----------|
| YOLOv5s | FP32 | CPU | 3.77 inf/s | 265 ms |
| YOLOv5s | **INT8** | CPU | **3.91 inf/s** | **256 ms** |
| YOLOv5s | FP32 | **GPU** | **25.83 inf/s** | **39 ms** |
| YOLOv5s | INT8 | GPU | 25.81 inf/s | 39 ms |
| InceptionV3 | FP32 | CPU | 10.48 inf/s | 95 ms |
| InceptionV3 | **INT8** | CPU | **10.40 inf/s** | **96 ms** |
| InceptionV3 | FP32 | **GPU** | **32.53 inf/s** | **31 ms** |
| InceptionV3 | INT8 | GPU | 32.53 inf/s | 31 ms |

> 关键结论：GPU 加速明显（YOLO 6.6x / Incept 3x），INT8 在 GPU 上无额外加速。

### 2.2 端到端管线延迟（含 adb 传输 + 预处理 + 后处理）

| 平台 | YOLO 后端 | YOLO 平均 | 全帧平均 |
|------|----------|----------|----------|
| QCS8550 板端 | CPU | ~900ms | ~3500ms |
| QCS8550 板端 | GPU | ~1550ms | ~4600ms |

> GPU 逐帧测试反慢：`snpe-net-run` 每帧重建 GPU 上下文，开销 ~800ms。持续流场景应用 `snpe-throughput-net-run` 才能发挥 GPU 优势。

### 2.3 LLM 性能

| 模型 | 平台 | 后端 | 延迟 |
|------|------|------|------|
| TinyLlama-1.1B-Chat-v1.0 | Mac M5 Pro (24GB) | MPS GPU | ~1650ms/帧 |
| TinyLlama-1.1B | QCS8550 CPU | 纯 ARM | 估计 >10s/帧 |
| TinyLlama-1.1B | QCS8550 HTP | — | **不可用**（版本不匹配） |

## 三、当前阻塞

| 问题 | 影响 | 根因 |
|------|------|------|
| **LLM 无法在板端运行** | LLM 必须在 Mac 上跑 | 板端 HTP runtime `v2.0.1` ≠ SDK `v2.22.6` |
| **HTP/DSP 全部不可用** | YOLO/Incept 不能走 DSP 推理 | 同上版本不匹配 |
| **测试数据全是空旷场景** | 只测到 KEEP_CENTER 一种决策 | KITTI 正常行驶无堵塞 |
| **合成障碍物测试失败** | YOLO INT8 不检测贴图 | INT8 量化 + 贴图不自然 |

### HTP 版本不匹配详情

```
板端 /vendor/lib64/:        QNN HTP runtime  v2.0.1.220706112757_38277
板端 /vendor/lib/rfsa/adsp/: libQnnHtpV73Skel.so (v2.0.1)
手头 SDK:                    QNN SDK  v2.22.6
结果:                        QNN_COMMON_ERROR_INCOMPATIBLE_BINARIES
```

**HTP 硬件存在且正常（Hexagon V73 + Adreno 740），仅 SDK 版本不兼容。**
